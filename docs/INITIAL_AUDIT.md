# 初始審查

這份文件記錄本次重構開始前的倉庫狀態。審查先讀過合約、測試、部署腳本、桌面錢包、紀錄檔與設定，沒有把編譯通過當成正確。

## 當時的架構

倉庫是一個 Hardhat 專案，外加一個 Electron 桌面錢包。

- `contracts/EcoToken.sol`：唯一的合約，同時負責 ERC-20、簽章鑄幣與質押。
- `test/EcoToken.test.js`：鏈上行為測試。
- `scripts/deploy.js`：部署那一份合約。
- `wallet/`：可安裝的桌面錢包，可轉帳、收款與質押。
- `records/`：一份用 A4 紙尺寸算出來的克數紀錄。
- 沒有後端、資料庫、網站或模型服務。

依賴是 Hardhat 2、Solidity 0.8.24、OpenZeppelin 5.7、ethers 6 與 Electron。網路設定有本機、Sepolia（鏈 ID 11155111）與一個未使用的 `l2` 欄位。

## 當時的合約行為

代幣名稱是 EcoToken，符號 ECO，小數 18。上限是 1,000,000 ECO。建構時如果初始供給大於或等於上限，部署會失敗，目的是保留後續鑄幣空間。

鑄幣函式是 `mintWithAttestation`。簽名使用 EIP-712，網域名稱是 `EcoToken`，版本 `1`，並綁定鏈 ID 與合約地址。同一筆 `actionId` 只能用一次。過期簽名、錯誤鏈、非證明人簽名、鑄給合約自己，都會失敗。直接把幣轉進代幣合約也會失敗。

質押寫在同一份代幣合約裡。`stake` 把 ECO 轉進合約並記帳，`unstake` 把同一數量轉回。沒有利息，也沒有區塊獎勵。

管理員使用 Ownable 兩段轉移。證明人就是當下的 owner，沒有獨立的證明人清單。轉帳沒有暫停功能，所以管理員不能凍結餘額。

## 當時的安全機制

有用的部分要保留：

- 供給上限。
- EIP-712 綁定鏈與合約。
- 同一筆紀錄不能領兩次。
- 簽名期限。
- 證明人轉移要經過接受。
- 不能把幣直接轉進代幣合約。
- 初始供給必須低於上限。
- 桌面錢包的私鑰以密碼加密，存在本機，不進 Git。

## 問題

1. **未經授權的克數經濟。** 合約把 1000 克寫成 1 ECO。這不是專案所有者設計的規則，也不能代表減碳或清運量。
2. **nonce 沒有被消耗。** nonce 出現在簽名裡，但合約沒有另外記錄它。防重放主要靠 `actionId`。
3. **證明人權限太集中。** 任何人只要成為 owner，就能簽任意數量，直到碰到上限。合約無法表達「這筆金額來自哪一版獎勵政策」。
4. **質押與代幣耦合。** 代幣合約自己保管質押，之後很難單獨處理活動鎖定。
5. **舊的 Sepolia 部署。** 本機曾經部署過舊合約 `0x444696e8926BBfce3B04B288D7983F286EC8B814`。那份合約仍使用克數介面，不能當成新系統。私鑰只留在本機 `.env`，沒有進入倉庫。
6. **沒有驗證平台。** 沒有使用者、影片、審核、資料庫或模型。桌面錢包不能提交環境活動。

## 應保留的檔案

- 桌面錢包的視窗、加密鑰匙圈與轉帳流程。
- Hardhat、Sepolia 設定與「拒絕主網自動部署」的原則。
- 測試裡對轉帳、上限、過期簽名、錯誤證明人與兩段所有權的斷言。這些斷言要改成新介面，不能刪掉。
- `records/action-1.csv` 與方法說明。它們是歷史紀錄，不再用來鑄幣。

## 建議的遷移

新合約使用提交 ID、獎勵金額與紀錄雜湊。Eco Points 留在鏈下政策檔，換算率未確認之前不鑄幣。質押改到獨立合約。舊的 Sepolia 地址繼續留在鏈上，但新錢包要改填新的代幣與質押地址。沒有得到明確指示之前，不重新部署。
