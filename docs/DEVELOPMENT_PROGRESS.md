# 開發進度

日期：2026-11-03。這次是安全與整合修正。沒有部署合約，沒有啟用正式鑄幣，也沒有下載模型權重。

## 這次找到的問題

- 部署者會自動成為證明人。所有權移交後，舊擁有者仍能簽名鑄幣。
- 抽獎回呼只檢查目前設定的隨機來源。換來源之後，舊請求可能被新來源回答，或原本的來源被拒絕。
- 管理員可以核准還沒有影片、也沒有驗證結果的草稿。
- 同一筆提交若換算已確認，重複呼叫領取會各自產生一筆授權。
- 近似重複被決策函式直接退件，而且和 SHA-256 完全相同混在同一個原因裡。

## 已修改

- `contracts/core/EcoToken.sol`：擁有者與初始證明人分開。所有權被接受後，舊擁有者的鑄幣權會移除。
- `contracts/rewards/EcoRewardManager.sol`：每個請求記住發出它的來源，回呼必須來自該地址。
- `contracts/test/TestRandomnessSource.sol`：測試可以指定回呼目標。
- `backend/src/server.ts`：審核資格、影片紀錄、SHA-256 完全相同檢查、單一獎勵授權。
- `backend/src/rewards/ledger.ts`：用行程內的 SQLite 交易與主鍵避免重複授權。這不是 PostgreSQL。
- `ai/verification/decision.py`：近似重複改為人工審核。
- 對應的合約、後端與模型測試。

## 測試

- `npx hardhat test`：21 通過。包含所有權移交、證明人撤銷、舊簽名失效、隨機來源更換，以及本機 Hardhat 鑄幣與重複提交拒絕。
- `npm test --prefix backend`：11 通過。包含 SIWE 登入、提交、影片紀錄、驗證、管理員審核、政策拒絕、單一授權與完全相同的 SHA-256。
- `python -m unittest discover -s ai/tests -v`：7 通過。

這些測試沒有連上 Sepolia，也沒有連上 PostgreSQL。後端流程測試裡的換算率只存在該測試，沒有寫進 `records/reward-policy.json`。

## 目前的使用方式

提交頁會把影片存到伺服器，MobileNetV2 看影格裡的物件。相符就自動核准並準備 ECO，不相符或重複就拒絕，沒有人工審核。獎勵是撿垃圾 0.5、回收 0.3、公園清理 1、海灘清理 1.5、種樹 2、環境活動 3。用 ECO 買抽獎券。活動取消才退票。CS2 皮膚由主辦者在鏈下發給得主。

## 仍需人工判斷
